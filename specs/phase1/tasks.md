# 实施计划

对应 [requirements.md](requirements.md) 与 [design.md](design.md)。下列任务在需求与方案确认前不开始。确认后按编号实施，完成一项再勾选一项。

- [ ] 1. 建立 crate 与前端工程
- 建立 Rust crate `duolinzao`（Axum、Tokio、SQLx）和 `web/` 下的 Vue3 + TypeScript + Vite 工程
- 增加 `config.example.toml`，启动时校验总管理、WebAuthn、SMTP、截止钟点、三餐餐后时刻、均分阈值、样本量下限和本地加密密钥；缺项则拒绝启动
- 由配置文件创建总管理，不提供总管理的邀请码注册
- _需求: 需求 1、需求 2、需求 18

- [ ] 2. 建立迁移、权限与审计底座
- 按设计写入账号、标签、食堂绑定、会话、报餐、菜谱、评分、评语、隐藏偏好、通知、LLM 渠道、审计和可修改设置的迁移
- 审计写入器拒绝记录密码、TOTP 密钥、会话令牌、邀请码原文、magic link 和 LLM key
- 保证未满 6 个月的审计不可被清除
- _需求: 需求 2、需求 15、需求 18

- [ ] 3. 完成注册、邀请码与食堂绑定
- 实现字符串账号 + 一次性邀请码注册，账号唯一
- 仅总管理和管理标签可发放邀请码
- 员工可绑定多个食堂；食堂管理人员与普通绑定分开存储
- _需求: 需求 2、需求 3、需求 7

- [ ] 4. 完成四种登录、新设备与会话
- 按 Passkey / WebAuthn、TOTP、邮箱 magic link、密码的顺序提供登录，密码仅作兜底
- 邮箱在使用 magic link 前绑定，注册不强制邮箱
- 新设备支持已登录设备扫码授权；也支持 TOTP 或邮箱验证后绑定本机 Passkey
- 同一账号的会话并行保留；提供查看设备、踢设备和解除 Passkey
- 食堂账号允许多账号、多 Passkey
- 在 Chrome 与 Edge 上验收登录、扫码和踢设备
- _需求: 需求 4、需求 5、需求 6

- [ ] 5. 完成班制、模板套用、自动报餐与覆盖
- 只实现「上二休四」和自定义排班；上二休四保存锚点日，并按工作 2 天、休息 4 天循环
- 新用户可以手动报餐；选定班制或完成过报餐之前不自动报餐
- 休息日不自动报餐，仍允许手动报餐
- 一键把预设套用到多天
- 同一用户、同一日期、同一餐次只保留一条报餐；手动覆盖模板，模板和自动任务不覆盖手动
- _需求: 需求 8、需求 9

- [ ] 6. 完成北京时间截止与管理员改单
- 到配置的北京时间钟点时，一次性锁定次日早、中、晚
- 锁定后拒绝员工和仅食堂身份的改单
- 总管理和管理标签可以在锁定后修改，并写审计
- 代码与示例配置不写死具体钟点
- _需求: 需求 10

- [ ] 7. 完成按食堂维护的菜谱
- 食堂人员只能维护被指定食堂的菜
- 员工只能看到所选食堂的菜谱
- 停用菜品只能来自显式操作
- _需求: 需求 7、需求 11

- [ ] 8. 完成明线评分、评语与暗线偏好
- 只接受已报过的餐，窗口为配置的餐后时刻起 7 日
- 分数只接受 −2、−1、0、1、2；无默认好评；只提交评语时拒绝
- 同一用户、日期、餐次、菜只保留一条评分，不提供改分和删除评语接口
- 评语最长 300 字，可选匿名；匿名时管理端不返回账号
- 员工端不展示菜品排行
- 每次成功打分后更新该用户对该菜的隐藏平均分；响应与界面不出现数值、倾向、权重、Elo
- _需求: 需求 14、需求 15

- [ ] 9. 完成选菜优化与强提醒
- 提供独立的候选菜视图，按明日预计就餐人的隐藏偏好排序和上色，更多人喜欢的靠前
- 无人评分的菜靠后，颜色不标注数字
- 样本量达到下限且可见均分低于阈值时，向食堂人员写入站内强提醒
- 强提醒不修改菜的启用状态
- 总管理可在运行中修改均分阈值和样本量下限
- _需求: 需求 12、需求 13、需求 15、需求 17

- [ ] 10. 完成统一模板生成器
- 只暴露 `POST /api/meal-templates/generate`
- 按配置者保存的顺序尝试本地脚本与 LLM；前一条失败再用下一条
- 至少支持 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages
- DeepSeek、通义和其它兼容服务通过 base URL 与模型名配置
- key 加密保存，接口不回传 key，服务端不内置供应商密钥
- 生成结果可以手改并保存为预设
- _需求: 需求 16

- [ ] 11. 完成站内提示与推送预留
- 一期提示写入站内通知，并提供读取接口
- `POST /api/push/reservations` 固定返回 `501 push_not_in_phase1`，不连接浏览器推送服务
- _需求: 需求 17

- [ ] 12. 完成导出、账号找回与镜像交付
- 总管理可导出食堂、菜谱、报餐、评分、评语和审计，排除密钥与密码哈希
- 总管理可重置密码或清除失效登录材料，使账号恢复可登录
- 构建包含前端产物与 Axum 二进制的 Docker 镜像；数据库由部署方单独运行
- 镜像与仓库保留 AGPL-3.0 许可证
- _需求: 需求 1、需求 18

- [ ] 13. 做一期验收测试
- 用 Rust 集成测试覆盖注册、会话、覆盖规则、锁定、评分窗口、匿名评语、强提醒不自动下架、渠道顺序和推送预留
- 用 Vue 测试覆盖登录顺序、员工端无排行、选菜页无内部术语
- 在 Chrome 与 Edge 上走通注册、登录、报餐、截止后拒绝改单、评分和食堂强提醒
- _需求: 需求 1、需求 4、需求 9、需求 10、需求 12、需求 13、需求 14、需求 16、需求 17
