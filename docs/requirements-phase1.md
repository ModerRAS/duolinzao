# 多邻灶（duolinzao）· 一期需求

产品名：**多邻灶**  
仓库 / crate：`duolinzao`（`ModerRAS/duolinzao`）  
定位：部门内部报餐网页，约 300 人、≤10 个食堂、三餐/天、**无支付**；交付 Docker，部署与备案自理；日后可再迁微信小程序。

技术栈：**Vue3**（前端）+ **Rust Axum**（后端）。

---

## 1. 角色与账号

| 角色 | 说明 |
|------|------|
| 员工 | 一人一账号；可绑定多个食堂；多设备 Passkey + 并行会话；可查看/踢设备、解绑 Passkey |
| 食堂 / 物业 | 同一批人管理指定菜谱；一食堂可有多账号，每账号可绑多设备 Passkey |
| 标签式管理员 | 通过标签进入管理能力 |
| 总管理 | 配置文件初始化；处理密码 / 账号找回 |

**注册**：字符串账号 + 管理员邀请码自助开通（各登录方式通用）。

---

## 2. 登录（无密码优先）

优先级：**Passkey / WebAuthn → TOTP → 邮箱 magic link → 密码（兜底）**。  
**不做短信 OTP**。

- 新设备：可用已登录设备扫码授权，或经 TOTP / 邮箱后再绑定本机 Passkey。
- 目标浏览器：Chrome / Edge（含 Windows）。
- 员工：一人一账号，多设备不互踢（可手动踢）。
- 食堂：支持多人多账号、多设备（避免绑死单机）。

---

## 3. 班制与报餐

### 3.1 班制（已简化）

只保留两种：

1. 固定 **「上二休四」**
2. **自定义排班**

已明确砍掉：上五休二、多班叠加、各食堂各自发布不同班制。

### 3.2 报餐规则

- **新用户默认不报餐**：必须自行选班制 / 完成报餐后，才有自动报餐。
- 模板可一键套到多天；**手动报餐覆盖模板**；同餐「后报覆盖先报」。
- 员工可绑定多个食堂；跨食堂时按所选食堂走。
- 一期：**早 / 中 / 晚三餐**，无夜宵。

### 3.3 截止

- **北京时间**提前一天固定时间点，一次性锁定次日三餐。
- 截止后：**仅管理员可改**，无其他改单权限。

---

## 4. 菜谱与选菜

- 菜谱按食堂建立与维护。
- **选菜优化**（独立能力）：按明日预计就餐人的**暗线偏好**，对候选菜上色 / 排序（更多人喜欢的靠前）。
- **强提醒**：当样本量足够且均分低于超管可配置阈值时，提醒食堂停用该菜；**不自动下架**。阈值可由超管编辑。

---

## 5. 评分：明线 / 暗线

### 5.1 明线（用户可见）

- 仅针对**已报过的餐**。
- 餐后 **1 周内**可对菜打分：**−2 ～ 2**。
- 可选**匿名评语** ≤300 字；按「餐次 + 菜」一条。
- 可只打分，**不可只写评语**；无默认好评。
- 员工端**不展示**菜品排行。
- 不可改他人分数。
- 评语主要给管理端看；软删，不开放删除接口。

### 5.2 暗线（后端）

- 每次明线打分，静默更新「人–菜」隐藏偏好。
- 用于选菜排序与强提醒。
- 界面**不出现**倾向 / 权重 / Elo 等说法。

---

## 6. 模板生成器（一期必做）

- 根据班制描述生成报餐模板（DSL / 脚本或 LLM），生成结果可手改预设。
- 后端只保留**统一接口**；按用户配置的渠道顺序选用。
- 渠道至少支持：**OpenAI 旧接口、OpenAI 新接口、Anthropic**。
- **用户自备 key / 模型**。建议配置顺序：OpenAI 兼容 → DeepSeek → 通义 → 其它。
